# チャット入力欄のオン/オフトグルと、オフ時の警告マーク

対応サービスのチャット入力欄のそばに PII Guard のオン/オフのトグルを置く。オフのときはこれまでどおり何も変えずに送るが、入力欄の文章に個人情報や機密文があれば警告マークを出し、そこから「オンにする」を選べるようにする。

## 現状

- オン/オフの設定 `enabled` は 1 つで、ポップアップの「マスキングを有効化」だけが切り替える。送信を横取りする 3 つの経路 (fetch、XHR、WebSocket) はすべてこの値を見て、オフなら本文に触れずに送る
- 拡張機能は入力欄の DOM に一切触れていない。検出は送信の直前に、送信される本文に対して行う
- 送信前の確認用サイドバーは、`<body>` 直下の Shadow DOM ホストに描く。ホストページの DOM ツリーには要素を挿入しない

## 要件

| ID | 要件 |
|---|---|
| R-01 | 対応サービスのチャット入力欄のそばに、PII Guard のオン/オフのトグルを表示する |
| R-02 | トグルはポップアップの「マスキングを有効化」と同じ設定 (`enabled`) を切り替える。どちらで変えても、もう一方と、開いているすべてのタブに即時反映する |
| R-03 | オフのとき、送信は一切変更しない (現行どおり)。サイドバーもモーダルも出さない |
| R-04 | オフのとき、入力欄の文章に個人情報か機密文が含まれていれば、トグルのそばに警告マークと件数を出す。含まれていなければ出さない。除外リストに登録した値は数えない |
| R-05 | 警告マークから「オンにする」を選べる。選ぶとオンになり、以後の送信で通常どおりサイドバーが開く |
| R-06 | オフの間の検出は端末内の正規表現と辞書だけで行う。入力欄の文章を LLM にも ML モデルにも渡さず、保存も通信もしない |
| R-07 | 入力欄が見つからないページでは何も表示せず、送信経路の動作にも影響しない |
| R-08 | ホストページの DOM ツリーに要素を挿入しない。サイトの再描画で壊れないよう、Shadow DOM の浮遊要素を重ねる |
| R-09 | 入力欄の読み取りは入力が止まってから 400ms 後に 1 回だけ行い、20,000 文字を超える分は見ない。入力の操作感を損ねない |
| R-10 | 開発版とストア版の両方で動く。新しい権限は要らない |

## 解釈として決めたこと

| ID | 決定 | 理由 |
|---|---|---|
| A-01 | 「オンにする」を選んだあと、サイドバーは送信時に開く (現行のオンと同じ)。入力中の下書きを対象に即座には開かない | 即座に開くには、伏せた文章を入力欄に書き戻す処理が要る。ChatGPT や Claude の入力欄は独自の編集 DOM で、書き戻しはサイトごとに壊れやすい。送信時に開く形なら既存の経路をそのまま使える |
| A-02 | トグルは全体の設定で、サイト別やタブ別にはしない | ポップアップの設定と同じ 1 つの値にしないと、表示が食い違う |
| A-03 | オフのまま送信するときは、警告が出ていても止めない | オフは「何もしない」という利用者の選択。止めると、それはオンと同じになる |

## 設計

| ID | 決定 | 対応 |
|---|---|---|
| D-01 | 新しいモジュール `browser-extension/composer-toggle.js` を作る。MAIN world に、sidebar.js の後、injected.js の前に注入する。`window.__localMaskMCP.composerToggle` として公開する | R-01 |
| D-02 | 入力欄の特定は 2 段階。まずサービスごとのヒントを試し、無ければ汎用の判定にする。汎用の判定は、画面内に見えている `textarea` と `[contenteditable="true"]` のうち、画面の下半分にあって面積が最大のもの。見つからなければ DOM の変化を監視して再探索する | R-01, R-07 |
| D-03 | 表示は `position: fixed` の Shadow DOM ホストを `<body>` 直下に置く。サイドバーが作る wrapper の外に置く (wrapper は `transform` を持つので、中に置くと fixed の基準がずれる)。入力欄の矩形の右上角の内側に重ね、入力欄の大きさの変化、スクロール、画面サイズの変化に追従する。入力欄が消えたら隠す | R-07, R-08 |
| D-04 | 見た目は高さ 24px のピル。盾のアイコン、「PII Guard」、スイッチ。オンは既存の accent 色、オフは灰色。オフで検出があるときは、ピルの左に橙の警告バッジと件数を出す。バッジを押すと小さなポップオーバーに種類別の件数 (例: メールアドレス 2、電話番号 1、機密と思われる文 1) と「オンにする」「閉じる」を出す。配色の明暗はサイドバーと同じ輝度判定 | R-04, R-05 |
| D-05 | 状態の同期: `enabled` を content.js の設定配信 (`broadcastSettings`) と `storage.onChanged` の監視に加える。ピルの操作は `set-enabled` メッセージで content.js に送り、content.js が `chrome.storage.local` に書く。書き込みが `onChanged` で全タブに配信され、各タブのピルとポップアップが更新される | R-02 |
| D-06 | オフ時の検出: textarea は `input` イベント、contenteditable は `MutationObserver` で変化を受け、400ms の debounce 後に文章を読む (`value` か `innerText`、先頭 20,000 文字)。`engine.maskAggregated(text, { userForceMaskEntries, mlEnabled: false })` を呼び、結果の `aggregated` から除外リストの値を除いた件数と `confidential` の件数を合計する。0 なら警告を消す | R-04, R-06, R-09 |
| D-07 | オンのときは入力欄を読まず、警告も出さない。送信時にサイドバーがすべて見せるため | R-06, R-09 |
| D-08 | 「オンにする」は `enabled: true` を書くだけ。サイドバーは次の送信で開く | R-05, A-01 |
| D-09 | 送信経路 (fetch、XHR、WebSocket) は変えない | R-03 |
| D-10 | `composer-toggle.js` を両方の manifest の `web_accessible_resources` と content.js の注入順に加える。STORE-STRIP は使わない | R-10 |
| D-11 | `PRIVACY.md` に、入力欄の読み取りは端末内の検出だけに使い保存も送信もしないことを 1 項目追記する | R-06 |

### サービスごとのヒント (D-02)

| サービス | 候補 |
|---|---|
| ChatGPT | `#prompt-textarea` |
| Claude | `div[contenteditable="true"].ProseMirror` |
| Gemini | `rich-textarea .ql-editor`、`div[contenteditable="true"][aria-label]` |
| Manus | `textarea` |

サイトの改修でヒントが外れても、汎用の判定で拾う。ヒントは 1 つの表にまとめ、更新しやすくする。

### ピルの状態

| 状態 | 表示 |
|---|---|
| オン | ピルはオン表示。警告なし |
| オフ、検出なし | ピルはオフ表示。警告なし |
| オフ、検出あり | ピルはオフ表示。左に警告バッジと件数 |
| 入力欄が無い | 何も表示しない |

## 非機能

- **性能**: 検出は正規表現と辞書だけ。debounce 400ms、20,000 文字で打ち切り。オンのときは入力欄を読まない
- **可用性**: 入力欄が見つからない、矩形が取れない、エンジンが未準備、のどの場合も黙って何もしない。送信経路には影響しない
- **セキュリティ**: 新しい権限なし。ホストページの DOM に要素を挿入しない。入力欄の文章は端末内の検出にだけ使う
- **運用**: サービスごとのヒントは 1 つの表。外れても汎用の判定で動くので、サイトの改修ごとの緊急対応を減らせる
