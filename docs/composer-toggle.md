# チャット入力欄のオン/オフトグルと、オフ時の警告マーク

対応サービスのチャット入力欄のそばに PII Guard のオン/オフのトグルを置く。オフのときはこれまでどおり何も変えずに送るが、入力欄の文章に個人情報や機密文があれば警告マークを出し、そこから「オンにする」を選べるようにする。

## 現状

- オン/オフの設定 `enabled` は 1 つで、ポップアップの「マスキングを有効化」だけが切り替える。送信を横取りする 3 つの経路 (fetch、XHR、WebSocket) はすべてこの値を見て、オフなら本文に触れずに送る
- 拡張機能は入力欄の DOM に一切触れていない。検出は送信の直前に、送信される本文に対して行う
- 送信前の確認用サイドバーは、`<body>` 直下の Shadow DOM ホストに描く。ホストページの DOM ツリーには要素を挿入しない

## 要件

| ID | 要件 |
|---|---|
| R-01 | 対応サービスのチャット入力欄のそばに、PII Guard のオン/オフのトグルを表示する |
| R-02 | トグルはポップアップの「マスキングを有効化」と同じ設定 (`enabled`) を切り替える。どちらで変えても、もう一方と、開いているすべてのタブに即時反映する |
| R-03 | オフのとき、送信は一切変更しない (現行どおり)。サイドバーもモーダルも出さない |
| R-04 | オフのとき、入力欄の文章に個人情報か機密文が含まれていれば、トグルのそばに警告マークと件数を出す。含まれていなければ出さない。除外リストに登録した値は数えない |
| R-05 | 警告マークから「オンにする」か「マスキングする」を選べる。どちらも、その場で入力中の文章を対象にサイドバーを開く。「オンにする」はあわせて設定をオンにする。「マスキングする」は設定をオフのままにする |
| R-11 | サイドバーで承認した結果を入力欄に書き戻す。書き戻せなかった場合は、入力欄を変えずにその旨を表示する |
| R-12 | サイトのスクリプトが、オン/オフや除外リストなどの設定を変えられないこと。設定の変更は、利用者が実際に PII Guard の UI を操作したときだけ受け付ける |
| R-13 | サイトが PII Guard の UI を隠したり動かしたり、偽の見た目をかぶせたりして、利用者に意図しないクリックをさせられないこと (クリックジャッキング) |
| R-06 | オフの間の検出は端末内の正規表現と辞書だけで行う。入力欄の文章を LLM にも ML モデルにも渡さず、保存も通信もしない |
| R-07 | 入力欄が見つからないページでは何も表示せず、送信経路の動作にも影響しない |
| R-08 | ホストページの DOM ツリーに要素を挿入しない。サイトの再描画で壊れないよう、Shadow DOM の浮遊要素を重ねる |
| R-09 | 入力欄の読み取りは入力が止まってから 400ms 後に 1 回だけ行い、20,000 文字を超える分は見ない。入力の操作感を損ねない |
| R-10 | 開発版とストア版の両方で動く。新しい権限は要らない |

## 解釈として決めたこと

| ID | 決定 | 理由 |
|---|---|---|
| A-01 | 警告マークの「オンにする」「マスキングする」を押した時点で、入力中の文章を対象にサイドバーを開く。承認した結果は入力欄に書き戻す | 利用者の指定。送信時まで待つ形は採らない。書き戻しは入力欄の種類ごとに方法が違い、サイトの改修で壊れうるので、書き戻せたかを毎回確かめ、失敗したら入力欄を変えない |
| A-04 | 「マスキングする」は設定をオフのままにする 1 回きりの操作。「オンにする」は設定をオンにしたうえで同じことをする | 2 つのボタンを別の意味にしないと、片方が要らなくなる |
| A-02 | トグルは全体の設定で、サイト別やタブ別にはしない | ポップアップの設定と同じ 1 つの値にしないと、表示が食い違う |
| A-03 | オフのまま送信するときは、警告が出ていても止めない | オフは「何もしない」という利用者の選択。止めると、それはオンと同じになる |

### サービスごとのヒント (D-02)

| サービス | 候補 |
|---|---|
| ChatGPT | `#prompt-textarea` |
| Claude | `div[contenteditable="true"].ProseMirror` |

サイトの改修でヒントが外れても、汎用の判定で拾う。ヒントは 1 つの表にまとめ、更新しやすくする。

### ピルの状態

| 状態 | 表示 |
|---|---|
| オン | ピルはオン表示。警告なし |
| オフ、検出なし | ピルはオフ表示。警告なし |
| オフ、検出あり | ピルはオフ表示。左に警告バッジと件数。押すと内訳と「オンにする」「マスキングする」「閉じる」 |
| 下書きの確認中 | サイドバーが開いている。確定で入力欄が伏せた文章に置き換わる |
| 書き戻し失敗 | 入力欄は元のまま。ピルに「入力欄に書き戻せませんでした」を数秒表示 |
| 入力欄が無い | 何も表示しない |

### Shadow DOM の中の目印 (テストと実装の共通の約束)

閉じた Shadow DOM の中は外から読めないので、ホスト要素の data 属性に状態と部品の位置を写す。テストはこれを読み、本物のマウス入力で押す。

| 属性 | 内容 |
|---|---|
| `data-pii-guard="composer-toggle"` | ピルのホスト (`html` 直下) |
| `data-pii-guard="persist-confirm"` | 保存の確認のホスト (`html` 直下) |
| `data-enabled` | `"true"` / `"false"` (アイコン) |
| `data-docked` | 下の段に置いているか (`"true"` / `"false"`) |
| `data-warn` | 警告の件数。オンのときは `"0"` (ピル) |
| `data-pending` | 保留中の確認の種類 (確認)。無ければ空 |
| `data-layout` | 部品の矩形 `[x, y, w, h]` の JSON。アイコンの側は `toggle`、`warn`、`turnOn`、`maskOnce`、`close`、確認は `confirm`、`cancel`。隠れている部品は `null` |

`data-pii-guard` 以外は、テスト用のフラグ `__pii_guard_e2e` が保存されているときだけ出る (D-17)。

ページの DOM に入れるもの: 下の段の場所取り `span[data-pii-guard="dock"]` (D-18)、背景色を付けた要素の印 `data-pii-guard-tint` と、その色を書いた `style[data-pii-guard="tint-style"]` (D-24)。

## 非機能

- **性能**: 検出は正規表現と辞書だけ。debounce 400ms、20,000 文字で打ち切り。オンのときは入力欄を読まない
- **可用性**: 入力欄が見つからない、矩形が取れない、エンジンが未準備、のどの場合も黙って何もしない。送信経路には影響しない
- **セキュリティ**: 新しい権限なし。ホストページの DOM に要素を挿入しない。入力欄の文章は端末内の検出にだけ使う。オン/オフは isolated world で保存し、ページ側からは変えられない (D-15)。UI へのクリックは、部品が完全に見えているときの本物の入力だけを受け付ける (D-17)

## 以前からあった露出とその対応

サイドバー (MAIN world) の「除外」とドラッグ登録は、以前から `add-allowlist` / `add-forcelist` / `remove-forcelist` メッセージで content.js に保存を頼んでいた。サイトのスクリプトも同じメッセージを送れるので、除外リストに値を足して以後の送信でその値を伏せさせない、ということができた。D-16 により、保存はサイトが触れない isolated world の確認を押したときだけ行うようにした。サイトのスクリプトがメッセージを送っても、利用者に確認が見えるだけで、押さなければ何も変わらない。

残る違いは操作感で、「除外」を押したあとに確認の「追加」を 1 回押す必要がある。除外リストへの追加は送信ごとの操作ではないので、この 1 回は許容できると判断した。
