# 動作ログ (1.7.1)

拡張機能がブラウザのコンソールに書いていたログをやめ、設定画面の「ログ」タブで見られるようにする。

## 現状と問題

| ID | 問題 | 根拠 |
|---|---|---|
| P-LG-01 | ページのコンソールに、送信する中身の先頭 160 文字を出している。伏せ字にする前の文が出るので、入力した文章がコンソールに残る | `injected.js` の `provider ws send:` (2026-10-28 に利用者が貼ったログ) |
| P-LG-02 | ログの URL に、接続用の値 (`verify=`、`k=`) と、利用者を表す ID (`/ws/user/user-…`) がそのまま出ている。`redactUrl()` が伏せる名前の一覧に無い | 同上 |
| P-LG-03 | LLM が見つけた値を、誤検出として捨てるときにログへそのまま出している (`dropped false positive "…"`) | `injected.js` の `mergeLlmDetect()` |
| P-LG-04 | ページの世界 (MAIN world) で出したログは、ページの `console` を通る。ページのスクリプトが `console` を差し替えていれば、その中身を読める。エラーの記録ツールにはコンソールの出力を集めて送るものがある | `injected.js` の `LOG`/`WARN` は `console.debug`/`console.warn` |
| P-LG-05 | コンソールのログは「詳細」レベルにしないと見えず、利用者が不具合を伝えるときに使いにくい | 2026-10-28 の調査で、利用者がログの表示と貼り付けに手間取った |

## 要件

| ID | 要件 |
|---|---|
| R-LG-01 | 拡張機能はブラウザのコンソールに何も書かない。ページの世界、content script、Service Worker、拡張機能のページ (設定、ポップアップ、Secure Composer、offscreen) のすべてで |
| R-LG-02 | 設定画面に「ログ」タブを置き、拡張機能の動きの記録を見られるようにする |
| R-LG-03 | ログは 14 日分だけ残す。それより古いものは消す |
| R-LG-04 | ログには、入力した文章、見つけた値、ファイル名、ファイルの中身、送信の中身、URL のパス・クエリ・フラグメント、接続用の値、アカウントや会話の ID を入れない |
| R-LG-05 | ログは端末の中 (`chrome.storage.local`) だけに置き、外へ送らない |
| R-LG-06 | ログはコピーできる (不具合を伝えるときに貼れる)。すべて消すこともできる |
| R-LG-07 | ログを書いても送信の処理は遅くならない。ログの量には上限がある |
| R-LG-08 | 権限を増やさない (1.5.1 から変えていない) |
| R-LG-09 | 拡張機能自身のエラー (例外) もログに残し、コンソールには出さない |

## 解釈として決めたこと

- **保存期間は 14 日:** 利用者の指示は「直近 1 週間〜2 週間」。長いほうの 14 日を残す期間にし、表示では「今日」「7 日」「14 日」を選べるようにする。
- **残すのは「何が起きたか」だけ:** 決まった種類の出来事、件数、サイトのホスト名、理由、の組み合わせにする。文章を入れられる欄は作らない (R-LG-04 を仕組みで守るため)。
- **細かいログは残さない:**
  - 次のものは、ログに残さず捨てる。
    - リクエストを 1 件ずつ記録したもの
    - WebSocket の送信を 1 件ずつ記録したもの
    - フックを入れたこと
    - LLM の待ち時間
  - 残すのは、利用者や開発者が「何かあったとき」に見たい出来事に限る。
    - 伏せ字にした
    - 止めた
    - 失敗した
    - 設定を変えた
    - クリックを無視した
- **エラーは名前と場所だけ:** 例外のメッセージには入力が混ざることがある (`JSON.parse` は失敗した文字列の一部をメッセージに入れる)。だから、メッセージは残さない。残すのは、例外の名前 (`TypeError` など) と、決まった場所の名前だけ。

## 設計

| ID | 決定 | 対応 |
|---|---|---|
| D-LG-01 | 共通の `browser-extension/diag-log.js` を置く。中身は 4 つ。<br>・出来事の一覧 (`CODES`)。種類ごとに、重さ (`info`/`warn`/`error`)、表示する日本語、受け付ける項目とその型を決める<br>・項目を検める `sanitize()`<br>・表示の文に直す `format()`<br>・保存と読み出し<br>すべての置き場所 (content script、Service Worker、設定画面、Secure Composer) が同じファイルを読む | R-LG-02, R-LG-04 |
| D-LG-02 | 項目の型は 4 つだけ。<br>・`int` (0 以上の整数)<br>・`bool`<br>・`enum` (決めた文字列の中の 1 つ)<br>・`host` (ホスト名。英小文字、数字、`.`、`-` で 253 文字まで)<br>トップレイヤーの要素の説明だけは、`layers` (タグ名、`popover` の値、`role`、モーダルかどうか、の組の並び。最大 6 件) を使う。<br>一覧に無い出来事、一覧に無い項目、型に合わない値は捨てる。文字列を自由に入れられる型は作らない | R-LG-04 |
| D-LG-03 | 保存は Service Worker だけが行う。<br>・content script と拡張機能のページは、`chrome.runtime.sendMessage({ type: "DIAG_LOG", entries })` で送る<br>・ページの世界のスクリプト (`injected.js` など) は、今のメッセージの経路 (`window.postMessage`、`source: "mask-mcp-inpage"`) で `type: "diag-log"` を content script に渡す。content script は、ページが偽った可能性があるものとして検め直し、出どころに `page` と付けて送る | R-LG-01, R-LG-05 |
| D-LG-04 | 置き場所は `chrome.storage.local`。<br>・日ごとに `diagLog:YYYY-MM-DD` (端末の時刻の日付) の配列に入れる<br>・日付の一覧は `diagLogDays` に入れる<br>・書き込みは Service Worker の中で 1 本の列に並べ、0.3 秒まとめてから書く (同時に書いて消し合わないため)。<br>1 件は `{ t, lv, src, site, code, d, n }`。`n` は回数 | R-LG-03, R-LG-07 |
| D-LG-05 | 同じ出来事が続くときはまとめる。同じ日、同じ種類、同じサイト、同じ項目のものが、直前の記録から 60 秒以内なら、新しく足さずに直前の記録の `n` を増やし、時刻を新しくする。<br>1 日に入れるのは 500 件まで。超えた分は捨て、上限に達したことを 1 件だけ残す | R-LG-07 |
| D-LG-06 | 古いログを消すのは 2 つの時。Service Worker が起動したときと、書くたび。<br>今日を含めて 14 日より前の日付の配列を消し、`diagLogDays` からも外す。<br>保存の上限で書けなかったときは、古い日から消して書き直す | R-LG-03 |
| D-LG-07 | 設定画面にタブを置く。<br>・「設定」と「ログ」の 2 つ。最初は「設定」<br>・「ログ」には、新しい順の一覧を出す。列は、日時、種類、場所、内容 (回数つき)<br>・期間 (今日 / 7 日 / 14 日) と種類 (すべて / 注意とエラーだけ) を選べる<br>・ボタンは「コピー」と「すべて消す」。消す前に確認を出す<br>・表示は `textContent` だけで組む。ページの世界から来た記録には「ページ側から報告」と添える<br>・開いている間に新しい記録が入ったら、表示し直す (`chrome.storage.onChanged`) | R-LG-02, R-LG-06 |
| D-LG-08 | `console.*` を呼ぶ場所はすべて消す。<br>・今の `LOG`/`WARN` は、D-LG-01 の出来事に置き換えるか、捨てる<br>・`browser-extension/` の中 (`vendor/` を除く) に `console.` が無いことを、テストで確かめる | R-LG-01 |
| D-LG-09 | 拡張機能のエラーを拾う場所は 4 つ。<br>・Service Worker、拡張機能のページ、offscreen: `error` と `unhandledrejection` を拾い、`error` の出来事にする<br>・content script: `window` に来るエラーのうち、ファイル名が自分の拡張機能のものだけを拾う。ページのエラーは拾わない | R-LG-09 |
| D-LG-10 | 書くのは、送信の処理が終わったあと。待たずに (`await` せずに) 送る。ログを書くのに失敗しても、送信の処理には影響させない (例外を外に出さない) | R-LG-07 |

## 非機能

- **プライバシー:** 残るのは決まった種類と件数とホスト名だけで、文章を入れる型が無い (D-LG-02)。ページの世界から来た記録も同じ検めを通る。
- **性能:** 送信の処理はログの書き込みを待たない (D-LG-10)。書き込みは 0.3 秒ごとにまとめる。量は 1 日 500 件、14 日で最大 7,000 件 (1 件 200 バイトとして約 1.4 MB) に収まる。
- **権限:** `storage` は今もある。新しい権限は要らない。
